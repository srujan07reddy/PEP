# Product Engineering Platform (PEP)

**Domain-Agnostic AI-Assisted ERP Evolution Framework**

## Vision
This framework is NOT an ERP and DOES NOT replace existing ERP systems. Instead, it is an **AI-assisted Engineering Governance Framework** that continuously evaluates, governs, analyzes, explains, and evolves existing ERP systems across any business domain. The framework behaves as an AI Chief Engineering Advisor capable of guiding ERP evolution through governance-driven analysis, explainable reasoning, intelligent prioritization, and strategic engineering roadmaps.

## 🚀 Key Features & Functionalities

### 1. Code & Architecture Intelligence
- **PEP Code Model & Engine Optimizer**: A multi-engine abstract architecture that normalizes output from parsers (like Tree-sitter, Semgrep) into a strictly typed semantic model.
- **Code Knowledge Graph**: Leverages Neo4j (via the `KnowledgeStore` interface) to parse codebases, generate dependency graphs, and infer system architecture.
- **Semantic Code Retrieval**: Uses Qdrant for vector similarity search, enabling deep contextual engineering memory.
- **Document Intelligence**: Integrates tools like NLP++ and Docling for extracting insights from complex unstructured organizational documentation into the `PEP Text Model`.

### 2. XAI & Traceability (Explainable AI)
- **Unified Evidence Model**: Normalizes extractions across all engines into verifiable `Evidence`.
- **Knowledge Compiler**: Stitches Evidence together into a heavily traceable Knowledge Graph.
- **Traceable Decisions**: Every recommendation generated by the platform ensures 100% explainability by tracing `Decision -> Recommendation -> Finding -> Evidence`.

### 3. Core Intelligence Engines
- **Architecture Intelligence**: Evaluates system boundaries, coupling, and patterns.
- **Security Intelligence**: Cross-references Code implementations against Security Policy nodes.
- **Quality Intelligence**: Correlates code complexity with engineering standards.
- **Organization Intelligence**: Analyzes structural alignment and drift between organizational policies and code implementation.
- **Evolution Engine (Difference Engine)**: Computes semantic drift across time (T1 vs T2), detecting architectural changes, new violations, and resolved findings.
- **Decision Board**: Automatically formats findings into boardroom-ready Architecture Decision Records (ADRs).

### 4. Domain Packs
The core platform remains strictly domain-independent. Specialized rules, workflows, AI opportunities, and industry standards are loaded dynamically via pluggable **Domain Packs** supporting industries such as: Education, Healthcare, Government, Manufacturing, Retail, Banking, and Enterprise.

## 🛠️ Technology Stack
- **Core Platform**: Python (Strictly typed models and abstract Engine interfaces)
- **Backend**: FastAPI, Uvicorn
- **Frontend**: React / Tailwind (Platform Console Dashboard)
- **AI & ML**: LangGraph, NLP++, Transformers
- **Databases & Vector Stores**: Neo4j (Graph Database), Qdrant (Vector Database), Postgres
- **Code Analysis**: Tree-sitter, Semgrep

## 📊 Outputs & UI Interfaces
- **Engineering Decisions (ADRs)**: A comprehensive roadmap detailing problems, alternatives, consequences, and recommendations.
- **Platform Console**: A React-based web dashboard allowing CIOs, CTOs, IT Administrators, Architects, and Compliance Officers to view real-time governance standards, codebase health, and engineering decisions.

## ⚙️ Getting Started
Ensure you have Python 3.x and Node.js installed.

1. **Install Backend Dependencies**:
   ```bash
   pip install -e .
   ```
2. **Start Backend Server**:
   ```bash
   cd apps/platform_console/backend
   python -m uvicorn main:app --reload
   ```
3. **Start Frontend Client**:
   ```bash
   cd apps/platform_console/frontend
   npm install
   npm run dev
   ```
